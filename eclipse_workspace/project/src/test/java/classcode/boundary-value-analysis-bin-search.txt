Selecting Test Cases Considering Boundary Value Analysis
From The Art of Software Testing, 3rd Edition

Boundary value analysis differs from equivalence partitioning in two respects:

1. Rather than selecting any element in an equivalence class as being representative,
boundary value analysis requires that one or more elements be selected such that each
edge of the equivalence class is the subject of a test.

2. Rather than just focusing attention on the input conditions (input space), test cases
are also derived by considering the result space (output equivalence classes).

Boundaries of the Input Equivalence Classes for BVA:
Valid EC - the set of arrays of nonempty size (>=1)
  BV: pick an array of size 1    // BV is Boundary Value
  BV: pick an array of size 2
Invalid EC - empty array
  BV: pick an empty array
Invalid EC - null reference
  BV: pick arr = null
Valid EC - key at arr[i] where 0 <= i < arr.length
  (key smaller than arr[0] is selected below)
  BV: pick array with key at index 0
  BV: pick array with key at index 1
  BV: pick array with key at index n-1
  BV: pick array with key at index n-2
Valid EC - key < all the array values (not in array)
  BV: pick a key smaller than arr[0], closest to it (since arr is assumed ordered)
  (at arr[0] already selected)
Valid EC - key > all the array values (not in array)
  BV: pick a key larger than arr[n-1], but just after it
  (arr[n-1] already selected)
Valid EC - key not in array but in arr[0] < key < arr[n-1]:
  BV: pick a key just above arr[0] closest to it
  BV: pick a key just below arr[n-1] closest to it
Valid EC - pick any int key
  done
